## How Render Builds

The service is configured as a **Node.js web service** (not Docker):

- **rootDir**: `server/`
- **buildCommand**: `npm install && npm run build`
- **startCommand**: `npm start`
- **Environment**: `NODE_ENV=production` is set in env vars (Render injects it during build + runtime)

Render's build process:
```
cd server/
npm install          # installs dependencies
npm run build        # runs: npx tsc --skipLibCheck
```

## Root Cause Tree

```
NODE_ENV=production (Render env var)
  └── npm install skips devDependencies
        └── @types/express not installed
              ├── TS7016: Cannot find 'express' declarations
              ├── TS7016: Cannot find 'bcryptjs' declarations
              ├── TS7016: Cannot find 'multer' declarations
              │
              └── AuthRequest extends Request
                    └── Request type = unknown/any (no @types/express)
                          ├── TS2339: body/query/params not on AuthRequest
                          ├── TS2339: file/files not on AuthRequest
                          └── TS2503: Express namespace not found
```

## Why It Passes Locally

| Environment | `NODE_ENV` | `npm install` behavior | @types installed? | Build result |
|-------------|-----------|----------------------|-------------------|-------------|
| Local dev | undefined | Installs ALL deps | ✅ Yes | ✅ Passes |
| npm ci | N/A | Installs from lockfile (all) | ✅ Yes | ✅ Passes |
| Render build | `production` | Skips devDependencies | ❌ No | ❌ Fails |

## Fix

**Move all `@types/*` packages from `devDependencies` to `dependencies` in `server/package.json`.**

These are declaration files (`.d.ts`), not runtime code. They are tiny and have zero impact on production bundle size or startup time. Moving them ensures they are always installed even when `NODE_ENV=production` causes `npm install` to skip devDependencies.

| `server/package-lock.json` | Regenerated by `npm install` |

## No AuthRequest Redesign Needed

The `AuthRequest extends Request` pattern at `server/src/middleware/auth.ts:16` is correct. It inherits all `body`, `query`, `params`, `file`, `files` properties from Express's `Request` interface (defined in `@types/express`). The only reason these properties appear missing is that `@types/express` itself is missing during the build. Once the @types package is moved to `dependencies`, `AuthRequest` works perfectly.
