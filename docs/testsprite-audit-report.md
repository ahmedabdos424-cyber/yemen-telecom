## 3) الأخطاء المكتشفة والمُعالجة

### 3.1 خطأ حقيقي: الوكيل الجديد لا يظهر في القائمة (أُصلح ونُشر)
- **السبب:** `src/hooks/useManagerState.ts` كان يضيف كائن الاستجابة الكامل `{agent, credentials}` إلى قائمة الوكلاء بدلاً من `created.agent`، فكان الاسم يُعرض فارغاً.
- **الإصلاح:** فكّ الغلاف عند الإضافة: `setAgents(prev => [created?.agent ?? created, ...prev])`.
- **التحقق:** `tsc --noEmit` سليم + اختبارات Vitest 7/7 ناجحة + اختبار E2E `82191e03` (14/14) بعد النشر.
- **النشر:** commit `21e2815` → deploy `dep-d9nvei9srm7s73fgup7g` → حالة **live** على Render.

### 3.2 خطأ خادم: 500 بدلاً من رسالة واضحة عند تكرار هاتف وكيل (توصية تحسين)
- `POST /api/agents` بهاتف مكرر يعيد `500 Internal Server Error` (تسريب خطأ `duplicate key value violates unique constraint "idx_agents_phone_unique"` في السجلات) بدلاً من `409/400` برسالة عربية.
- **التوصية:** التقاط أخطاء القيد الفريد في `server/src/routes/agents.ts` وإرجاع `409 {error: "رقم الهاتف مستخدم مسبقاً"}`.

## 4) الثغرات والقيود الموثقة

| القيد | الشرح | الوضع |
|---|---|---|
| إبطال جلسة "الجهاز B" | كل أدوار قاعدة البيانات (`manager`/`agent`/`seller`) معرّفة بـ `session-exempt`، فأي دخول جديد لا يُبطل سابقته | غير قابل للاختبار — سلوك تصميمي مقصود |
| لا توجد شاشة عملاء للمدير | واجهة المدير لا تحتوي مسار `/manager/customers` (الـ API موجود: `POST /api/customers`) | اختبار "إنشاء عميل" FE أُلغي؛ يبقى مغطّى عبر الـ API |
| نافذة تعديل الوكيل بلا حقل اسم مستخدم | النافذة تعرض الاسم/الهاتف/المنطقة فقط (قرار تصميمي — بيانات الاعتماد غير قابلة للتعديل) | موثّق في خطة الاختبار لمنع خطوات خاطئة |
| بيانات الاختبار تتراكم في الإنتاج | الاختبارات تولّد وكلاء بأسماء/أرقام شبه ثابتة؛ قيود `users.username` و`agents.phone` الفريدة تسبب فشل إعادة التشغيل | يُلزم تنظيف يدوي (SQL) بين الركضات؛ خطط جلسة اليوم استخدمت أسماء فريدة زمنياً |
| `gh` CLI غير مصادق | لا يمكن متابعة النشر عبر GitHub CLI | يُتابع عبر Render MCP |
